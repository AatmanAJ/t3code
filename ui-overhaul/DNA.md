## 0. How to cite this document

1. Every proposal cites at least one rule ID: `DNA-<AREA><n>`. Areas: P principles, C colour, T type, S shape, SP spacing, D density, M motion, V voice, I icons, L layout, X mobile and cross-surface, ID identity, K do-not-touch.
2. Rules (`DNA-*`) are binding. A proposal may break a rule only by saying so, citing the rule, and giving a reason that is stronger than the evidence under it.
3. Drift items (`DRIFT-n`, section 14) are audit leads, not rules. A proposal may fix a drift item by moving the code toward a rule; it must cite both the `DRIFT-n` and the rule it restores.
4. Evidence is cited as `path:line` (code), `[shot: name]` (a file in `screens/dna/`), or `[measured]` (Playwright `boundingBox()` or `getComputedStyle()` against the running app; the numbers are reproduced here, not in the repo). Class counts come from a tokeniser run over the 792 non-test `.ts`/`.tsx` files in `apps/web/src/components`; a count includes variant-prefixed uses (`sm:text-sm` counts as `text-sm`) unless it says "unprefixed".
5. If a value in this document disagrees with the code, the code wins and the document is wrong; say so in the proposal.

## 1. Principles (DNA-P): the maintainers' own words

These come from `AGENTS.md` and `docs/internals/web-ui.md`. They outrank every taste rule below.

- **DNA-P1 Performance is a design constraint.** "css animations causing gpu spikes, lists being hard to render" are named regressions (`AGENTS.md:17`). "No continuously repainting animations; they peg the GPU on high-refresh displays" (`AGENTS.md:197`). A visual idea that needs a per-frame repaint is rejected before it is judged on looks.
- **DNA-P2 Obvious, minimal, no slop.** "software that feels obvious", "the smallest model that makes the correct behavior unsurprising", "yagni" (`AGENTS.md:35-37`). Do not add chrome, steps, or tokens to look thorough.
- **DNA-P3 UI is dumb and truthful.** "UI stays dumb" (`AGENTS.md:185`); users "notice a dropped frame, a lying spinner, and a stale label" (`AGENTS.md:197`). Every status label, count, and spinner must reflect real state.
- **DNA-P4 Primitives own their look.** Pick a `variant` or `size` from `components/ui`; do not restyle with `className`; layout classes (width, flex, margin, position) go on the parent (`AGENTS.md:188`; `docs/internals/web-ui.md:5-10`). Lint rule `shadcn/no-restyle` enforces it. A look that belongs to one feature lives in that feature's component.
- **DNA-P5 Style with Tailwind in the owning component.** Global CSS is only for generated Markdown, custom elements, animations, runtime theme variables, and Electron integration; theme-only rules use `@variant dark` / `@variant light`, never `.dark` selectors (`docs/internals/web-ui.md:14-22`).
- **DNA-P6 Compose slots, do not copy markup.** `ComposerBanner` is the reference: one object of small slots that own their classes (`docs/internals/web-ui.md:24-39`).
- **DNA-P7 Every way in has a way out.** "Snooze needs unsnooze. Close needs reopen. A one-way door is a bug" (`AGENTS.md:74`). New states ship with their reverse and a place to see it.
- **DNA-P8 Hit every surface.** A change is not done until entry points (chat, settings, command palette, keybinding), clients (web, desktop, mobile), connection modes (local, relay, tunnel) were considered (`AGENTS.md:65-76`).
- **DNA-P9 Remote ready, multi-surface.** The same UI is served by `npx t3`, `app.t3.codes`, Electron and phones (`AGENTS.md:19-31`). Nothing may assume a local filesystem, a mouse, or a native titlebar.

## 2. Colour (DNA-C)

### 2.1 How colour is built (as implemented)

Layers, bottom to top:

1. `:root` default palette: `index.css:1094-1208`. Light values are declared at `:root`, dark values inside `@variant dark` (`index.css:1168-1207`). `dark` is a custom variant bound to `.dark` on `<html>` (`index.css:3`).
2. `[data-app-sidebar]` re-scope: the sidebar subtree redefines `--background`, `--card`, `--border`, `--sidebar-*` and gets its own dark values (`index.css:1213-1255`, and again for themed palettes `index.css:1503-1528`).
3. Named/custom themes: when `<html data-theme-id="...">` is set, `index.css:1264-1329` remaps every semantic token to a `--app-theme-<role>` variable written at runtime by `applyThemePalette` (`themePalette.ts:1452-1475`, role-to-variable map `themePalette.ts:1368-1430`). 61 roles (`packages/shared/src/themePalettes.ts:30-92`).
4. Contrast layer: every text/border token a component can read is re-derived as `--contrast-*` from `--appearance-contrast-*` (`index.css:1538-1651`; written by `appearanceContrast.ts:3-10`). Setting range 50 to 200, default 100 (`packages/contracts/src/settings.ts:106-112`).
5. Tailwind mapping: `@theme inline` at `index.css:174-289` maps `--color-foreground` to `--contrast-foreground`, `--color-border` to `--contrast-border`, `--color-muted-foreground` to `--contrast-muted-foreground`, `--color-primary` to `--primary`, and so on; radii at `index.css:284-289`. `apps/web/vite/tailwind.ts:1-12` is only the Vite plugin wrapper (it contains no colour or theme mapping).

Because components use `text-foreground`, `text-muted-foreground`, `border-border`, they get the contrast layer for free. Components that read raw `--foreground` do not.

Roles that themes do NOT recolour: success, info, guest, diff, provider and channel identity colours (`index.css:1257-1261`). Error, warning and update are themeable.

### 2.3 Accent, status, diff, selection

- **Accent (brand) colour** is `--primary`: `#1b4ed8` light, `#346bf1` dark (`index.css:1111`, `1179`). ### 2.6 How a generated palette derives from canvas + accent

`createVividThemeColors(appearance, canvas, accent)` (`themePalette.ts:620-754`) is what runs for short-format environment themes (`hooks/useEnvironmentTheme.ts:21-32`), the theme editor (`ThemeEditorPanel.tsx:267`) and VS Code import (`vscodeThemeImport.ts:234`). Rules it encodes:

- Dark vs light by canvas luminance < 0.179 (`:634`).
- Every surface = canvas lightness shifted by a fixed delta, tinted with the accent hue at chroma min(0.045, max(0.008, 0.22*accent chroma)): surface 0.015, sidebar 0.045, raised 0.05, overlay 0.075, border 0.12 (light) / 0.16 (dark), input 0.16 / 0.21, secondary 0.06 / 0.10, muted 0.04 / 0.06, accent surface 0.08 / 0.13, message surface 0.10 / 0.16 (`:639-681`). Direction is darker for light themes, lighter for dark.
- Text is solved to at least 7:1 on canvas (`:651`); muted text to 4.705 (light) or 5.082 (dark) (`:653`, `:805-814`); readable foregrounds on tinted surfaces to 4.6:1 (`:683-688`).
- Error and warning are the fixed standard hexes `#fb2c36/#c10007` and `#fe9a00/#bb4d00` (light), `#fb414a/#ff6467` and `#fe9a00/#ffb900` (dark), re-solved for contrast on the theme's tint (`:571-618`).
- The CTA colour is not the accent: `messageAction` = accent lightness +/-, hue rotated by +50 degrees (`:655-659`).
- Worked example, computed by calling the function: dark seed `#1a1b26` + accent `#7aa2f7` gives sidebar `#1d263b`, surface `#191f2e`, raised `#212837`, overlay `#272e3d`, text `#e7efff`, muted `#878c9a`, border `#37445d`, CTA `#d3a0ec`. ### 2.8 Rules

- **DNA-C1 Tokens, not literals.** Colour in a component is a semantic Tailwind token (`text-foreground`, `text-muted-foreground`, `border-border`, `bg-card`, `bg-accent`, `text-warning-foreground`...). New hex/oklch literals in components are rejected; a missing role is added to the 61-role set in `packages/shared/src/themePalettes.ts` and mapped at `index.css:1264-1329` so themes and mobile receive it. Evidence of the norm: 581 semantic status/accent token uses vs 82 raw Tailwind palette uses in `components` (see DRIFT-9).
- **DNA-C2 One chromatic voice.** The default product is neutral zinc/neutral surfaces with one blue (`--primary`). Chroma elsewhere is functional: status, diff, provider and project identity. A new screen must still read as grey-plus-one-blue in the default theme.
- **DNA-C3 Surfaces step by lightness, then a hairline.** Light: canvas `#fcfcfc`, sidebar `#fafafa`, card/popover `#ffffff`. Dark: sidebar `#000`, canvas `#0a0a0a`, card/popover `#111`. Separation is a 1px low-contrast border (1.24:1 light, 1.11:1 dark) plus the fill step, not a shadow, for anything that sits in flow.
- **DNA-C4 Two text levels plus disabled.** Primary text is `text-foreground`; secondary is `text-muted-foreground` (4.71 / 5.08:1, tuned on purpose, `themePalette.ts:802-803`); disabled is `opacity-64` (`button.tsx:9`). Do not invent a third grey with an opacity modifier: `text-muted-foreground/70` renders at 2.73:1 on the light canvas. `secondary-label`, `placeholder`, `icon-muted` are aliases of muted and exist so themes can diverge them; use the role that names the job.
- **DNA-C5 Contrast floors.** Normal text >= 4.5:1; muted >= 4.7 light / 5.08 dark; theme-generated text >= 7:1; generated status foregrounds >= 4.6:1 on their tint. Text smaller than 14px must not use a colour below 4.5:1. Icons and borders that carry meaning >= 3:1 (the existing `border` token is a decorative hairline and does not meet that; do not use it as the only cue).
- **DNA-C6 Status semantics are fixed.** success = emerald, warning = amber, error and destructive = red, info = blue, update = primary, guest = fuchsia. Text uses `*-foreground`, icons and fills use the base, tinted panels use `*-surface` (8% light, 16% dark). Themes do not recolour success/info/guest/diff (`index.css:1257-1261`), so never encode meaning in a theme's accent.
- **DNA-C7 Diff is green/red by default and colour-blind switchable.** Added = success family, removed = destructive family, both through `--diff-*`; never hard-code `text-green-*` for a diff.
- **DNA-C8 Light, dark, system are resolved once, early.** Components never read `prefers-color-scheme`; they use `@variant dark` / `light` or tokens that already flip. The boot script and `resolveThemeAppearance` stay in lockstep (`themeBoot.test.ts`). A new persisted appearance key must be added to the boot script and its parity test.
- **DNA-C9 Everything routes through the contrast layer.** Text and border colours used by components are `--contrast-*` via Tailwind tokens so the Contrast slider works. New component CSS uses `var(--contrast-foreground)` not `var(--foreground)` (as `index.css:1829` does).
- **DNA-C10 The sidebar is its own scope.** Sidebar tokens come from `[data-app-sidebar]`; a portaled sidebar (mobile sheet) must opt into the same scope or it will render root tokens (see DRIFT-2).
- **DNA-C11 Glass is a recipe, not a decoration.** Floating surfaces (menus, popovers, toasts, dialogs, details card, composer, glass-variant tooltips) use one of `dropdown-glass`, `dialog-glass`, `surface-glass`, `alert-glass` (`index.css:341-444`): blur 12px (16px dark), saturate 1.14 (1.08 dark), alpha from the user's Glass opacity setting, default 80, written to `--glass-opacity` at runtime (`index.css:117-119`, `147-148`; `settings.ts:104`; `routes/__root.tsx:309-319`). Panels, sidebar, rows and cards in flow are never glass.
- **DNA-C12 Grain belongs to chrome.** A 3.5%-opacity noise tile is baked into the sidebar and main surface backgrounds (`index.css:1688-1712`; `ui/sidebar.tsx:244,582`), never as a fixed overlay (a full-viewport overlay was removed because it raised idle GPU cost, `index.css:1688-1694`). A surface floating over the body must opt in with `surface-grain` or it will look flat against the body.
- **DNA-C13 Generated themes follow the generator.** Any theme work (editor, import, `t3 theme`) goes through `createVividThemeColors`; do not hand-tune a derived role, override it via `colors{}` (`docs/user/appearance.md:102-104`). New built-ins keep muted at 4.705 / 5.082 and text >= 7:1.
- **DNA-C14 Raw palette hues are for identity only.** Raw `text-sky-600` style classes are acceptable for project monogram hues (`projectIconColors.ts`), provider marks and file-type icons; not for status (see DRIFT-9).

### 3.4 Rules

- **DNA-T1 System fonts, one size ladder.** Interface text is the platform UI font. The ladder is 12 (meta) / 14 (body) / 20 (dialog title) / 24-30 (hero), with 11 and 10 reserved for dense metadata and counters. A new size needs a reason that the existing steps cannot meet.
- **DNA-T2 14px is the default reading and control size on desktop; 12px is the label size.** Row titles, menu items, inputs, buttons, composer and chat prose are 14. Metadata, descriptions, tabs, tooltips, chips are 12. Do not build a screen whose primary content is 12px or whose chrome is 16px on desktop.
- **DNA-T3 Touch and narrow widths scale controls up, not content.** Below 640px or on `pointer: coarse`, controls use `text-base` (16px) and taller hit areas; the pattern is `text-base sm:text-sm` (`button.tsx:9`, `menu.tsx:127`, `input.tsx:64`).
- **DNA-T4 Everything must survive the Interface font size setting.** Use rem-based classes; the 12-20px root range scales the chrome. Sizes in px (monogram 8.25px, code settings) are the documented exceptions and follow their own settings.
- **DNA-T5 Weight carries hierarchy, not size.** 400 body, 500 for titles/labels/buttons/selected, 600 for headings and emphasis, 700 only for the monogram glyph. No `font-bold` in chrome.
- **DNA-T6 Line height comes with the size token.** Custom sizes ship their line-height (`--text-2xs--line-height`, `index.css:181,183`). Prose uses `leading-relaxed` (1.625); single-line controls use fixed heights (`leading-8.5` style) so text never shifts a row.
- **DNA-T7 Mono is for machine-typed values.** Code, terminal, diff counts (`+20 -0`), version strings (`v0.164.0`), IDs, numeric readouts (slider values, diagnostics tables), the project monogram, and literal paths/commands. Not for branch names in the details card, not for shortcuts (`Kbd` is `font-sans`, `kbd.tsx:7`), not for labels.
- **DNA-T8 Numbers that update use `tabular-nums`.** Durations ("Working 9s"), counts, diagnostics, sliders (181 uses).
- **DNA-T9 Truncate in rows, wrap in prose.** Dense rows `truncate`; long paths use middle/start truncation components (`ui/middle-truncate.tsx`, `StartTruncatedPath.tsx`); prose wraps and uses `text-balance`/`text-pretty` in headings and short descriptions (5 and 7 uses).
- **DNA-T10 Overline labels are the only uppercase.** `uppercase tracking-widest` at 10-11px is for page eyebrows and table headers (`standalone-page.tsx:61`, markdown table headers `index.css:2124`); sentence case everywhere else.

- **DNA-S3 Hairline borders, not outlines.** Component edges are 1px, `border-border` (decor) or `border-input` (form controls), or 60/50% variants inside groups. 2px is reserved for focus, selected-node outlines and blockquote rules.

- **DNA-S5 Shadows are long, low and offset downward.** Negative spread, large blur, 40-90% black (`0 16px 40px -18px`); never a short dark drop shadow.
- **DNA-S6 The right panel stays flush.** It is a column with a left hairline, not a rounded card; the rounded glass card is the Thread details object only.
- **DNA-S7 Dividers separate groups, not rows.** Inside a grouped list the divider is `border-t border-border/50`; do not stack a border on every row of a flat list.
- **DNA-S8 Pick the glass utility for the role.** `dropdown-glass` for anchored popups and the details card, `dialog-glass` for modal dialogs, `surface-glass` for ghost-glass buttons, `alert-glass` for tinted alerts.

- **DNA-SP5 Reading column is capped.** Chat lane 46rem (736px) comfortable, 72rem wide, 100% full (`index.css:2212-2218`); settings/page content 896px; descriptions `max-w-xl`. No line of prose runs wider than the lane.
- **DNA-SP6 Vertical rhythm is 8 / 10 / 32.** Within a row 8px, header-to-group 10px, between sections 32px; do not introduce a fourth section gap.

## 7. Motion (DNA-M)

### 7.1 What animates today

**Panels (the maintainers' headline rule).** Sidebar, right panel and terminal drawer open and close instantly by default. The Panel animations slider runs 0-400 ms in 25 ms steps, default 0 (`settings.ts:113-122`, `:323-326`; `AppearanceSettingsPanel.tsx:381-418`; `docs/user/appearance.md:44-49`). The comment on the default is the reason: "Zero avoids per-frame layout work from width/height transitions" (`settings.ts:323`). Mechanics: the layout root exposes `--panel-animation-duration` and `data-panel-animations="true|false"` (`AppSidebarLayout.tsx:361,389`; measured `data-panel-animations="false"` on the sidebar wrapper), and every panel transition is gated by `[[data-panel-animations=true]_&]:` (`ui/sidebar.tsx:311,323,522`, `PreviewPanelShell.tsx:142`, `PersistentThreadTerminals.tsx:255`, `ChatView.tsx:3193`, `WorkspacePageHeader.tsx:18`). `usePanelAnimationSettings` makes animation active only if duration > 0, `prefers-reduced-motion` is not set, and the navigation is not suppressed (`panelAnimations.ts:30-38`); switching threads suppresses for two animation frames so thread changes never replay panel motion (`panelAnimations.ts:11-28`; `docs/user/appearance.md:48-49`). Easing is `ease-out`.

**Duty-cycled indicators (stepped, not continuous).**

- `status-pulse`, 2s, `steps(6)`, opacity 1 to 0.5, used on Working/terminal status dots (`index.css:223, 309-323`; 9 uses, behind `motion-safe:` at `ThreadStatusIndicators.tsx:767,831,853,992`).
- `skeleton`, 2.4s, `steps(4)`, opacity 1 to 0.55; "however many bars sit under it, the compositor draws a handful of discrete frames per cycle ... the difference between ~14 and ~288 updates" on 120 Hz (`index.css:220, 290-308`; 6 uses).
- `status-ping`, 2s, `steps(8)`, burst then hold (`index.css:224, 324-338`).
- `live-tool-shine` (running tool label sweep) 2.2s `steps(30)`, only under `prefers-reduced-motion: no-preference` and not forced-colors (`index.css:541-555`); `live-activity-focus` 2.2s `steps(30)` which turns itself off under reduced motion (`index.css:581-632`).
- Spinners: `visible-animate-spin` and `Spinner` pause when off-screen via `--visible-animation-state` set by an observer (`index.css:557-561`; `lib/visibleAnimation.ts:13-26`; `ui/spinner.tsx:7-34`), and are wrapped in `motion-safe:`.
- Measured: with the default settings, idle home and idle thread views had zero running animations (`document.getAnimations()` returned 0) [measured].

**One-shot transitions.**

- Streaming markdown: each new block fades in over 600ms ease-out, opacity only, only while `data-streaming` and `prefers-reduced-motion: no-preference`, via `@starting-style` so reopening a finished thread never replays it (`index.css:2107-2122`).
- Popovers/menus: scale 0.98 plus opacity, ~150ms (`popover.tsx:90`); tooltips `transition-[scale,opacity]`.
- Dialogs: 200ms `ease-in-out` scale/opacity/translate, backdrop `transition-all duration-200` (`dialog-styles.ts:2,5`); route modals (Settings, Usage) scale 0.985 plus opacity over 150ms `ease-out` (`AppRouteModal.tsx:55`). Neither is gated by the Panel animations setting.
- Toasts: transform .5s `cubic-bezier(.22,1,.36,1)`, opacity .5s, height .15s (`toast.tsx:568`).
- Control feedback: buttons `transition-[box-shadow,scale]` with `active:scale-[0.97]` (`button.tsx:9`); send button `hover:scale-105` (`ComposerPrimaryActions.tsx:313`); `transition-colors` 72 uses, `transition-opacity` 61, `transition-transform` 32; durations `duration-150` 37, `duration-200` 23, `duration-100` 6, `duration-180` 4; slider thumb 120ms (`index.css:990-993`). `transition-none` 39 uses.
- Attention: settings search target pulse 650ms x2 (`index.css:900-914`), the mobile composer view transition (`index.css:17-76`), sidebar drag label 200ms `step-end` (`index.css:2342-2353`), preview load bar 5.3s decelerating (`index.css:2305-2326`).
- Theme change: `.no-transitions` forces `transition-duration: 0s` for the whole tree while the palette swaps (`index.css:1086-1092`; `useTheme.ts:326-344`), so a theme switch never animates colours.
- Reduced motion: 25 files carry `motion-reduce:` (36 uses), 21 `motion-safe:` uses, 25 `prefers-reduced-motion` references outside tests.

The sidebar artwork is a static SVG with no animation (`SidebarStageBackdrop.tsx`, no `animate`/keyframes).

### 7.2 Rules

- **DNA-M1 Instant is the default.** Anything that changes layout size (sidebar width, right panel, terminal drawer, page header padding) is instant unless the user raised Panel animations above 0, and then it uses `--panel-animation-duration` via the `data-panel-animations` gate. A new panel-like surface adds itself to that gate, never its own duration.
- **DNA-M2 Nothing repaints continuously.** A running animation must be one of: (a) a one-shot under about 700ms (the preview load bar is the one longer exception), (b) a stepped, duty-cycled keyframe (`steps(n)`, long holds) such as `status-pulse`, `skeleton`, (c) paused when not visible. `animate-pulse`, `animate-bounce`, an unstepped infinite loop, a CSS animation on `width/height/top/left/box-shadow/filter/backdrop-filter`, or an animated gradient is rejected.
- **DNA-M3 Animate opacity and transform, nothing that reflows.** Micro-interactions change colour, opacity, shadow or scale only. Width/height/grid-row transitions exist only behind the panel gate or inside `AnimatedHeight` (`AnimatedHeight.tsx`).
- **DNA-M4 Duration ladder.** 100 to 150ms for hover/press/colour, 150 to 200ms for popups and modals, 600ms is allowed only for the streaming fade. Easing is `ease-out`; decelerating `--ease-drawer` (`index.css:192`) is for things that slide or pop in. A new duration needs a reason.
- **DNA-M5 Every animation has a reduced-motion branch.** Gate with `motion-safe:` / `motion-reduce:` or a `prefers-reduced-motion` query; panel animation also honours the OS setting automatically.
- **DNA-M6 Spinners are the shared `Spinner`.** It is visibility-aware. Do not hand-roll `animate-spin` on a Lucide icon (DRIFT-8).
- **DNA-M7 Streaming never replays.** New content may fade in while a turn streams; opening, switching to or reloading a finished thread shows its final state immediately.
- **DNA-M8 No motion on theme or appearance change.** Wrap palette swaps in the `no-transitions` window.
- **DNA-M9 Status must not lie.** A pulsing or spinning indicator means real work is in progress; stop it when work stops (see DNA-P3).

### 8.2 What the voice is

- **Sentence case, always** (title case only in status pill labels, DRIFT-11). Buttons and menu items are short imperatives or noun phrases: Settle, Snooze, Add project script, Create theme, Update all, Commit & push. Product and proper nouns keep their case (T3 Code, VS Code, Codex).

### 8.3 Rules

- **DNA-V1 Sentence case.** Capitalise the first word and proper nouns only, in buttons, menu items, headings, tabs, settings titles, status labels, toast titles.
- **DNA-V2 Buttons are verbs, destinations are nouns.** "Settle", "Add project script", "Open diff"; tabs and settings are nouns ("Files", "Typography"). A confirm button names its action ("Delete thread"), not "Confirm" (DRIFT-13).
- **DNA-V3 Say what failed, then why.** Toast title = failed action in plain words; description = actual cause or how to proceed. Never ship "An error occurred." where the cause is known (DRIFT-12 lists the fallback sites).
- **DNA-V4 One error prefix.** Prefer "Could not <verb> <object>" (90 existing titles). Do not add new "Failed to" / "Unable to" titles; no contractions in titles.
- **DNA-V5 Explain in place, once, briefly.** One short description under a setting; at most two sentences; end with a period; include the consequence or default. No tooltips as the only explanation.
- **DNA-V6 Second person, no theatre.** Use "you/your" or the imperative. No "Please", "Oops", "Sorry", exclamation marks, emoji, or marketing adjectives. "We" is reserved for onboarding and the draft hero invitation.
- **DNA-V7 Use the product vocabulary.** Thread, project, settle/un-settle, snooze/wake, worktree, environment (technical, settings, palette), computer (onboarding and hosted pages), surface. Do not coin synonyms (archive vs settle, sleep vs snooze, workspace vs worktree).
- **DNA-V8 Reverse actions are named as pairs.** Settle/Un-settle and Snooze/Wake are the existing pairs; any new one-way action ships with a named reverse (DNA-P7).
- **DNA-V9 In-progress labels end with a single ellipsis character.** "Updating…", "Searching messages…" (153 uses of U+2026 vs 110 of "..."; the character wins, DRIFT-14). Menu items that open a further choice end with "…" ("Custom…").
- **DNA-V10 Counts and times are literal.** "Settled (0)", "Working 9s", "Worked for 10s", "3m"; no rounding words ("a few", "recently").

### 9.2 Rules

- **DNA-I1 Lucide first, one stroke.** Use Lucide at its default 2px stroke (2.25 only for check marks that need weight). A new icon comes from Lucide; custom SVGs are for brands, file types and the monogram.
- **DNA-I2 Three sizes.** 16px (`size-4`) for control and menu icons, 14px (`size-3.5`) beside 12px text and in compact rows, 12px (`size-3`) for status/meta/tab icons. `size-4.5` and above are touch-only or empty-state sizes. Pair size with the text beside it (16 with 14px text, 14 with 12px).
- **DNA-I3 Icons are muted until active.** Default `--control-icon-color`/`--sidebar-icon-color`; foreground on hover or selected; status colour only for status.
- **DNA-I4 Never icon-only without a name.** Icon buttons carry `aria-label` and a tooltip with the shortcut (`PanelLayoutControls.tsx:56-130`).
- **DNA-I5 Projects are monograms.** Do not replace the monogram with a generic folder; the hash colour and 2-letter mono glyph are the project's identity everywhere (sidebar rows, breadcrumb, palette, settings).
- **DNA-I6 Provider and editor brands keep their own colour.** Do not recolour provider glyphs to the theme; recolouring is a user setting per provider.
- **DNA-I7 Spinners and morphs stay on the shared components.** `Spinner` for loading, `MorphIcon` for two-state toggles (DNA-M6).

## 11. Mobile and cross-surface (DNA-X)

- **Shared**: the palette source (`packages/shared/src/themePalettes.ts`) feeds both web CSS variables and mobile uniwind variables (`createMobileThemeVariables`, `apps/mobile/src/lib/mobileTheme.ts:320-444`; generated at build by `scripts/generate-uniwind-themes.mts`, `package.json:47`). Mobile theme ids: `t3-code` (default) plus the five built-ins, light and dark each (`generated-uniwind-theme-names.json`; `themePalettes.ts:3-5`). The mobile default palette is the web default: screen `#fcfcfc`, foreground `#27272a`, primary `#1b4ed8`, border `#e4e4e7` (`generated-uniwind-default-theme-variables.json`, light block). Roles, contrast helpers (`themeColorWithContrast`, `mobileTheme.ts:212`) and status semantics are the same.
- **Mobile-only**: Material You theme and "Material You Layout" on Android 12+, which change shapes, spacing and controls independent of theme (`docs/user/appearance.md:17-22`; `mobileTheme.ts:19`; `materialYouPalette.android.ts`). Mobile does not follow environment themes (`appearance.md:14-15`).
- **Diverges**: DM Sans (Regular, Medium, Bold) bundled instead of system fonts (`app.config.ts:116-118`, `global.css:17-19`; mono falls back to `monospace` on Android); a different type scale where the same class is larger: `text-3xs` 11, `text-2xs` 12, `text-xs` 13, `text-sm` 14, `text-base` 16, `text-lg` 18, `text-xl` 21, `text-2xl` 26, `text-3xl` 30 (`global.css:22-39`, `src/lib/typography.ts:1-12`) versus web 10 / 11 / 12 / 14 / 16 / 18 / 20 / 24 / 30; platform symbols (`expo-symbols`, 133 files) instead of Lucide (2 files); native navigation and sheets.
- **Web at phone width is a third thing**: the web app below 768px swaps the sidebar for a sheet, uses the touch size variants (default button 36px; header icon buttons measured 32px), sets composer text to 16px and shows a docked pill composer with controls below [shot: dna-mobile-home-light-390x844, dna-mobile-sidebar-dark-390x844]. It follows web tokens, not the native app.

Rules:

- **DNA-X1 One palette, three renderers.** A colour role exists once, in `themePalettes.ts`; web maps it in `index.css`, mobile in `mobileTheme.ts`. A web-only colour hack is a bug on mobile.
- **DNA-X2 Same token name, same meaning, not same pixels.** `text-xs` is 12px on web and 13px on mobile; proposals specify px or the role (label, caption, body) when they cross surfaces.
- **DNA-X3 Mobile keeps the web's information hierarchy** (thread rows, status vocabulary, composer-bottom, settle/snooze) while using native controls and fonts; it is not a reskin target for web typography.
- **DNA-X4 Phone-width web must work without hover.** Anything revealed on hover (row actions) has a touch affordance (`any-hover` variant, `index.css:8-15`).

## 12. Identity: the three things that make it T3 Code (DNA-ID)

Contrast set: the maintainers position T3 Code against Claude Desktop, Codex App, Cursor Glass and Conductor (`AGENTS.md:5`). I did not inspect those apps; the three traits below are defined by what this codebase does, and each names the structural choice that a lookalike would have to give up. The other contrast is the default shadcn dashboard look (card grids, KPI tiles, rounded-2xl everywhere, coloured gradients), which the primitives were deliberately tuned away from.

**DNA-ID1 A thread inbox, not a file tree.** The sidebar is a flat list of 78px two-line thread rows: project monogram tile, project name, live status ("Working 9s", "Done", a relative time), title, provider glyph, and on hover the Snooze (clock) and Settle (check) actions; a "Settled (n)" shelf below; Settle/Un-settle and Snooze/Wake as paired verbs (`threadActionMenu.logic.ts:131-138`). The product's mental model is triage of agent work. Evidence: `SidebarThreadRow.tsx:1272`, [shot: dna-thread-explain-light-1440x900], [shot: dna-stream-t2500-light-1440x900] (a new thread shows "Working 1s" in the row while the timeline says "Working for 2s" / "Thinking"). A change that turns the sidebar into a project tree, a card grid or a tabbed workspace switcher breaks this.

**DNA-ID2 A quiet flat canvas with a few floating glass objects.** Everything in flow is flat: grey-white canvas, 1px hairlines, no shadows, flush panels. The things that float over the canvas are few and recognisable: the 736px composer (22px radius), the 280px Thread details card top-right (22px radius), popups and toasts, all the same translucent blurred recipe, with a radius ladder 6-8-10-18-22. Add the mono accents inside that quiet field: project monogram tiles, `+20 -0` diff counts, version strings, file chips with language badges, inline code. Evidence: `ComposerSurface.tsx:21,48`, `ThreadDetailsCard.tsx:126`, `index.css:341-444`, [shot: dna-home-light-1440x900], [shot: dna-thread-explain-dark-1440x900]. Stable builds are not decorated further: the blueprint (Dev) and night-sky (Nightly) header art, and the same art inside the send button, are environment identification that only appears on those channels (`SidebarStageBackdrop.tsx:8-22`, `ComposerPrimaryActions.tsx:313-318`; setting `environmentIdentificationMode` artwork/pill/none, default artwork). The screenshots in this document are from the Dev channel and so show that art; a Beta/Latest build shows a plain sidebar header and a flat `bg-message-action` send button. Treat the art as a deliberate environment marker (and it is static SVG), not as brand chrome to extend to production.

**DNA-ID3 Obvious, instant, plain-spoken.** Panels open at 0 ms; indicators are stepped; nothing loops; the UI reports real state ("Working 9s", "Worked for 10s", "3m"); copy is sentence-case imperative, 14px/12px system type, no marketing, one hue. That is the "software that feels obvious" the maintainers ask for (`AGENTS.md:35,197`). Where a product could add weight (gradients, decorative motion, illustrated empty states), T3 Code removes it: the empty thread says one line, "Send a message to start the conversation." Evidence: `settings.ts:323-326`, `index.css:309-323`, section 8.

A fourth asset, not a trait but a moat: **themes as a first-class system** (6 palettes with light and dark halves, mix-per-appearance, VS Code import, `t3 theme set`, 61 roles, contrast slider, glass opacity, interface font size). Users run forks and custom palettes (`AGENTS.md:13`); any redesign must stay expressible through the theme roles.

### 16.2 How the numbers were produced

- Tokens and contrast: a Playwright script created a probe element per CSS variable, read `getComputedStyle`, converted any CSS colour to sRGB through a 1x1 canvas read-back, composited alpha over the canvas actually behind it, and applied the WCAG 2.x relative-luminance formula. Built-in theme contrast used the same formula on hex values converted from the OKLCH literals with `culori`. The generated-palette example called `createVividThemeColors` directly.
- Geometry: `locator.boundingBox()` and `getComputedStyle` on `[data-thread-item]`, `[data-chat-header]`, `[data-thread-details-card]`, `[data-slot=menu-popup]`, `[data-settings-page-scroll]` and others, at 1440x900 with `colorScheme` light and dark.
- Class counts: a script tokenising every non-test `.ts`/`.tsx` under `apps/web/src/components` (792 files) on whitespace/quotes/braces, stripping variant prefixes for the base counts (`sm:text-sm` counts as `text-sm`; unprefixed counts are quoted where it matters). `apps/web/src` as a whole (1,163 files) gives nearly identical shares.
- The helper scripts live in `/tmp/t3code-pw/dna/` (outside the repo) and were not committed.
