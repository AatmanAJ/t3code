## 3. Findings

### F-12-01 Collapsed toast stack hides older errors, warnings and actionable notices while their timers run

- Severity: P1
- Surface: all
- Evidence: `components/ui/toast.logic.ts:15-21` (`shouldHideCollapsedToastContent` returns true for every toast after the first); `components/ui/toast.tsx:558-561, 648-649` (`not-data-expanded:pointer-events-none not-data-expanded:opacity-0`); `toast.tsx:577-588` (peek 12 px, scale 0.1 per index). Measured at 1440x900 light with a 100 ms poll of the DOM: an error toast added at t=0 and a success toast at t=0.4 s; at t=1.1 s the error's content `opacity: 0`, `pointer-events: none`; it expired at t=5.0 s, readable for 0.4 s [shot: 12-toast-error-buried-light-1440x900]. Four toasts: the fourth is `data-limited`, opacity 0, with no "+1" cue [shot: 12-toast-stack-collapsed-light-1440x900, 12-toast-stack-expanded-light-1440x900, dark variants]. At 390x844 a persistent (`timeout: 0`) "Permissions have changed" notice with an "Open Connections" action is fully hidden behind a "Thread completed" toast [shot: 12-toast-mobile-light-390x844, 12-toast-mobile-dark-390x844].
- Current: only the newest toast is legible; older ones show as 12 px slivers until the pointer or focus enters the viewport. Base UI pauses timers only on hover or focus, so a hidden error keeps counting down.
- Proposed: stop burying content that asks for attention. In `toast.tsx` `Toasts()` replace the `hideCollapsedContent` argument with the toast: change the signature to `shouldHideCollapsedToastContent(visibleIndex, count, toast)` and return `false` when `toast.type` is `"error"` or `"warning"` or `hasVisibleToastAction(toast.actionProps)`. Because a visible toast must not be covered, render those toasts in the expanded geometry: delete the collapsed transform classes at `toast.tsx:577-588` (`not-data-expanded:h-(--toast-calc-height)`, the `--toast-peek`/`--toast-shrink` translate and the `--toast-scale` scale) so up to 3 toasts stack at natural height with the existing `--toast-gap` (12 px). Three toasts of 68-150 px fit under 450 px, inside a 600 px high window. Keep the Base UI `limit` of 3; the hidden fourth is the oldest and stays alive.
- DNA: DNA-P3 (UI truthful: a notice that exists but cannot be read is a lying state), DNA-D6 (degrade, not hide).
- Effort: S
- Risk: there is no unit test for `ui/toast.logic.ts` today; add `ui/toast.logic.test.ts` for the new signature and for `buildVisibleToastLayout`. Visual regression: toast column grows taller when 3 are present, covering more of the Thread details card (see F-12-37).
- Upstream-eligible: yes (fix-shaped, files untouched by #24865).
- #24865: not addressed (toast files untouched).

### F-12-02 Every toast defaults to 5 s: 299 of 302 error toasts vanish before a long message can be read

- Severity: P1
- Surface: all
- Evidence: `routes/__root.tsx:193,233` mount `<ToastProvider>` with no `timeout` or `limit`; Base UI `ToastProvider` defaults `timeout = 5000`, `limit = 3` (`@base-ui/react@1.5.0/toast/provider/ToastProvider.js:25-29`). Inventory: 456 of 472 sites pass no `timeout`. Of the 302 `type: "error"` sites 299 use the default (the exceptions are `GitActionsControl.tsx:1275,1408` and `chat/useMultipleModelSend.ts:255`); of 37 `warning` sites 35 do (exceptions `onboarding/WelcomeWizard.tsx:182`, `promptLinks/linkedPrompt.ts:9`). Explicit values elsewhere: `timeout: 0` x7 at the call (plus the three project-clone states through a shared options object), `1500` x1 (`CommandPalette.tsx:308`), `5_000` x1, clone done `8_000`, anchored `1000` x2, and the git set (`GitActionsControl.tsx:1275,1338,1349,1408,1431`). The git actions already follow a better policy: errors `timeout: 0`, success `dismissAfterVisibleMs: 10_000` (`components/GitActionsControl.logic.ts:45-59`). Measured: "Thread ID copied" visible 0.7 + 4.76 s = ~5.5 s [shot: 12-toast-thread-id-copied-light-1440x900]; a 190-character `EACCES` error gets the same 5 s.
- Current: a copy confirmation and a multi-line failure with a path to read share one lifetime.
- Proposed: one policy, in one place. Add `applyToastDefaults(options)` to `toast.logic.ts` (pure, unit-testable) and export a wrapped manager from `toast.tsx`: `const baseManager = Toast.createToastManager<ThreadToastData>(); export const toastManager = { ...baseManager, add: (o) => baseManager.add(applyToastDefaults(o)) }`; pass `baseManager` to `<Toast.Provider toastManager={baseManager}>`. Rules (an explicit `timeout` always wins): `error` and `warning` get `timeout = clamp(8_000, 3_000 + 40 * (title.length + description.length), 20_000)` and `priority: "high"` for `error` (see F-12-17); any toast with `actionProps` gets at least 10_000; `success`, `info` keep 5_000 (copy confirmations drop to 2_500 under F-12-28). Hover, focus and window blur still pause the timer (Base UI).
- DNA: DNA-P3, DNA-P2 (smallest model: one default, not 472 decisions), DNA-V3.
- Effort: S
- Risk: `GitActionsControl.browser.test.tsx:150`, `ServerUpdateAction.browser.test.tsx:54`, `ReopenClosedViewShortcut.browser.test.tsx:69` build `{ ...actual.toastManager, add: spy }`, which keeps working because the wrapper is a plain spreadable object; `MediaActions.test.tsx:67` replaces the whole module. Verify `update`, `close`, `promise` and the internal subscribe key still reach the base manager. More persistent errors mean more clutter: the `limit` of 3 and F-12-01 keep the column bounded.
- Upstream-eligible: yes.
- #24865: not addressed.
