# 20 copy-and-voice audit

Status: complete (code-read plus three live DOM text dumps; no screenshots, nothing saved from the running app).
Repo `5f64c5eb`. Paths are relative to `apps/web/src/components` unless prefixed (`apps/mobile/src`, `apps/desktop/src`, `packages/...`).

## Method

- Extracted 6,020 unique string candidates (JSX text, `title=`, `aria-label=`, `placeholder=`, `description=`, `label=`, and `title|label|description|message:` object props) from 792 non-test files in `apps/web/src/components`, plus targeted greps of `apps/mobile/src`, `apps/desktop/src`, `packages/contracts/src/keybindings.ts` and `docs/internals/glossary.md`. About 2,800 are multi-word user-facing strings; those were classified by term, casing, terminal punctuation, ellipsis, pronoun and tone. Legacy sidebar (`LegacySidebar.tsx`, DRIFT-20) excluded from counts.
- Live DOM text dumps (synthetic data only) of Settings nav, Diagnostics, Source control, Scheduled tasks, Keybindings and the sidebar at `localhost:5733`, to confirm which labels users actually see. The dev build predates #24865 (composer placeholder still reads "Ask for changes, send follow-ups, or attach images").
- Toast and error wording is already catalogued: F-12-11 (stock fallback), F-12-12 (prefixes), F-12-13 (jargon), F-12-30 (punctuation), F-12-31 (filler), F-10-35 (computer/environment/machine), F-10-36 (ellipsis), F-09-19 (provider disabled message), F-09-20, F-09-38, F-09-39. They are cited, not redone.
- Canonical vocabulary: `DOCS-DIGEST.md` "Product vocabulary" plus `docs/internals/glossary.md` (Environment, Project = "environment-local workspace record", Worktree, Thread, Turn, Session = "provider runtime attached to a thread", Provider, Provider instance). Note the glossary defines **session** as a provider runtime, so "Restart agent session" is correct usage and `chat`/`task`/`conversation` for a thread are the drift.

## Verdict in four lines

1. Tone is clean: 0 emoji, 1 exclamation in web chrome ("Copied!"), 1 "Please", no blame wording beyond "Invalid ..." titles. The voice problem is vocabulary and casing, not attitude.
2. Sentence case holds in about 95% of chrome (126 of 126 settings-search titles; 47 of 48 sampled dialog and empty-state titles). The exceptions cluster in four places: generated keybinding labels (about 90 rows), sidebar status pills, the Diagnostics page, and the About update button.
3. One concept routinely has three to five names: the machine a server runs on (environment 117 strings, machine 29, backend 26, server 37, computer 11), a thread (thread 197, chat 21, conversation 7, and "task" on mobile), a branch ("ref"), and the built-in browser (four names).
4. Mobile and desktop-native copy fork from web for the same action ("New task" vs "New thread", "You're up to date!" vs "Up to date").

### F-20-01 Provider-disabled error shows an id the user cannot use and a project UUID

- Severity: P1
- Surface: all (CLI, MCP, composer error banner)
- Evidence: `apps/server/src/orchestration-v2/ThreadManagementService.ts:287-296` builds `Provider instance "${instanceId}" is disabled for project ${projectId}.`; root cause and reproduction are F-09-19. Passing the driver name `claude` instead of the built-in instance id `claudeAgent` prints `Provider instance "claude" is disabled`, although nothing is disabled and `claude` is not an instance.
- Current: three wording faults in one sentence: the glossary term "Provider instance" shown to users, the id echoed is whatever the caller typed, and the project is a UUID.
- Proposed: wording only (server change is a dependency, rule 4). Unknown id: `Provider "claude" is not set up. Available providers: codex, claudeAgent. Add one in Settings, Providers.` Known but off: `Provider "claudeAgent" is turned off for sample-app. Turn it on in Settings, Providers.` (project title, never the id). UI follow-up as in F-09-19: show it in the thread error banner with an "Open provider settings" action.
- DNA: DNA-V3, DNA-V7
- Effort: XS for the copy (S together with F-09-19's tag split)
- Risk: `ThreadLaunchService.test.ts` and `ProviderContinuationService.test.ts` assert the error tag, not the text; scripts that match the old sentence break.
- Upstream-eligible: yes (small message fix)
- #24865: not addressed

### F-20-03 One thread state, two label sets, three casings, and "Done" collides with "settle"

- Severity: P2
- Surface: web (mobile has a third set, area 15)
- Evidence: pill labels `Sidebar.logic.ts:1076,1085,1094,1154,1163` ("Pending Approval", "Awaiting Input", "Guest Request", "Plan Ready", "Completed"), rendered through `ThreadStatusIndicators.tsx:813-830,913`; row labels `sidebar/SidebarThreadRow.tsx:655-703` ("Approval", "Input", "Request", "Limited", "Woke", "Done"); lifecycle row "Completed" (`chat/V2LifecycleRow.tsx:222`); toast "Thread completed" (F-12-14); mobile `apps/mobile/src/features/threads/thread-list-v2-items.tsx:79-115` copies the row set, while its detail screen says "Woke from snooze" (`ThreadDetailScreen.tsx:836-838`). - Current: a finished unread thread is "Done" in the row, "Completed" in the pill and toast, and the user's own action to close it is "Settle" (documented as "mark a thread done").
- Proposed: one `THREAD_STATE_LABELS` const in `Sidebar.logic.ts` used by pill and row; sentence case ("Pending approval", "Awaiting input", "Guest request", "Plan ready"); row short forms stay short but the tooltip shows the long form; "Done" becomes "Completed"; "Woke" becomes "Woke from snooze" (mobile's wording); aria "Dismiss wake notice".
